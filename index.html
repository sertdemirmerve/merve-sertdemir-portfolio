Olist E-Commerce — End-to-End Data Analytics Platform

An end-to-end analytics build on Olist's public Brazilian e-commerce dataset — from raw CSVs to a star-schema warehouse to a four-page Power BI dashboard, closing with churn and revenue-forecasting models in Python.

112,101orders analyzed

Problem / goal

Take unstructured order data and turn it into something reliable enough for executive reporting — with proper staging, a queryable warehouse, and dashboards that refresh on a schedule instead of a one-off spreadsheet.

What I did

  • Loaded 9 source CSVs into a SQL Server staging database via SSIS (9 tables, 7 primary keys, 6 foreign keys, 5 indexes)

  • 7.74% of orders were delivered late; health_beauty is the top revenue category
  • small_appliances was the fastest-growing category year over year

Personnel & Payroll Database — Error Detection & Validation

A relational SQL Server database for tracking staff, departments and payroll — rebuilt from a university-course script that failed to run, by tracing and fixing five separate integrity issues rather than starting from scratch.

5errors diagnosed
5tables
2engines cross-checked

Problem / goal

Diagnose why an existing script kept failing, and turn it into something that runs cleanly and enforces real referential integrity — the same instinct needed when reconciling a source system against a target one.

What I did

  • Identified an orphaned code fragment outside any CREATE TABLE statement causing a syntax error
  • Found salary records pointing to personnel IDs that didn't exist — a foreign key violation — and rebuilt them against the real IDs
  • Removed duplicate constraint and computed-column definitions causing "already exists" errors
  • Fixed three ID columns missing IDENTITY, which were causing NOT NULL violations on insert
  • Reordered the script so foreign keys are added after data load with WITH CHECK validation, instead of silently accepting inconsistent data
  • Independently re-verified the corrected logic against an equivalent SQLite schema

Key findings

  • All 5 structural and referential-integrity errors traced to a specific root cause and resolved
  • Corrected logic ran error-free on a second engine (SQLite) as an independent cross-check

Completed · Personal project

Breast Cancer Classification — Model Comparison & Interpretability

A comparison of four classification algorithms on the Breast Cancer Wisconsin dataset, using cross-validation to avoid picking a "winner" that only looks good on one lucky split — then explaining the chosen model's decisions with SHAP.

4models compared
0.996CV ROC-AUC
5-foldcross-validation

Problem / goal

Show that model selection based on a single train/test split can be misleading, and that any analysis needs a validation step — the same principle behind reconciliation in a business context, applied here to machine learning.

What I did

  • Compared Logistic Regression, Random Forest, SVM (RBF) and XGBoost on the same dataset
  • Ran 5-fold cross-validation on each model instead of relying on a single split
  • Used SHAP to explain which features drove individual predictions, not just which mattered on average

Key findings

  • On a single split, Random Forest looked strongest — but 5-fold CV showed Logistic Regression and SVM were actually the most consistent (ROC-AUC 0.996 ± 0.005)
  • The three most influential features — worst area, worst concave points, mean concave points — line up with known clinical indicators of malignant tumors
